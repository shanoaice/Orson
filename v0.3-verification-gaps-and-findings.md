## 2. Missing behavioral tests (backlog)

Priority reflects risk, not effort. Items marked **BUG** reproduce a defect that exists in the current tree.

### 2.1 Process lease, session lifecycle, and teardown

**BUG — `AlpmSession.TryCreate` bypasses the exclusive process lease.**
`src/Orson.Alpm/AlpmSession.Seams.cs:15-36` calls `TryInitializeHandle` and `new AlpmSession(handle)` without touching `s_activeLease`. `TrySeamContractTests.TryCreate_Success_SetsSessionAndNullFailure` therefore opens a second session while `IsolatedAlpmEnvironment` already holds one; disposing the second session runs `ReleaseProcessLeaseInternal()` and releases the *first* session's lease.

**BUG — `AlpmSession.UnregisterAllSyncDatabases` still retires the root domain.**
`src/Orson.Alpm/Interop/Lifetime.cs:176-180` has `RootLifetime.InvalidateHandles` call `Invalidate(...)` on the root, and `src/Orson.Alpm/AlpmSession.cs:397-399` calls both `InvalidateHandles` and `InvalidateSyncDatabases`. Unregistering all sync databases therefore invalidates the session, `LocalDatabase`, local package views, option views, and the callback stamp. This is the same cascading-invalidation defect that Phase 1 fixed for `SyncDatabase.Unregister`. `LifetimeTests.InvalidateHandles_*` currently pins the wrong behavior.

**BUG — ADR 0011's stale-instance epoch rule is unimplemented.**
`src/Orson.Alpm/AlpmSession.cs:39-40` declares `s_sessionEpoch` and `s_current`. `Acquire` and `ReleaseProcessLeaseInternal` write them; nothing reads them. A stale instance can release a newer session's lease.

Missing tests:

- `Acquire` while a session is active throws `InvalidOperationException`.
- A failed `Acquire` (invalid root/dbpath) releases the lease, and the next valid `Acquire` succeeds.
- A finalizer-released session (`SafeAlpmHandle.ReleaseHandle`) releases the lease without the test calling `ReleaseProcessLeaseInternal()` (`LifetimeGcPathTests` calls it manually, masking the real path).
- `TryCreate` honors the lease, and its failure path does not steal it.
- Every public member on a disposed session throws `ObjectDisposedException`; double `Dispose` is a no-op (`_disposeStarted`).
- `UnregisterAllSyncDatabases` throws while `CurrentTransaction` is set, and leaves `LocalDatabase`, its package views, and `AlpmOptions` valid when idle (see the BUG above).

### 2.2 Cached reads and database/facet invalidation

- `Database.Name` is the last remaining `field ??=` cached member (`src/Orson.Alpm/Database.cs:121-130`). Warm it, invalidate by `Unregister()`, `Transaction.Commit()`, and `AlpmSession.Dispose()`, then read it again; the second read must still throw `AlpmLifetimeException`.
- `SyncDatabase.Update()` and `AlpmSession.UpdateDatabases()` must retire prior package views from that database (even when the download fails) while the `SyncDatabase` wrapper stays usable (`_stamp = Lifetime.Capture()`).
- Exercise `FetchHandler` outcomes: `FetchResult.Success` (`Update` returns `true`), `FetchResult.UpToDate` (`false`), `FetchResult.Error` (throws and still invalidates views).
- Facet matrix in `DatabaseServerTests`:
  - `AddServer` / `SetServers` retire a previously captured `Servers` view but leave `SyncDatabase` package views alive (ADR 0017).
  - `RemoveServer(missing)` answers `false` and must **not** retire a previously captured `Servers` view (`SyncDatabase.cs:146-149`).
  - The same three rules for `AddCacheServer` / `RemoveCacheServer` / `SetCacheServers` against `CacheServers`.
  - `Unregister()` and `Update()` cascade into captured `Servers` / `CacheServers` facet views.
  - `ChildLifetime.Facet(...)` throws after the parent domain was invalidated (`Lifetime.cs:242-248`).

### 2.3 Package views, loaded packages, snapshots, versions

**BUG — `Transaction.AddPackage` / `RemovePackage` read `pkg.Name` before their guards.**
`src/Orson.Alpm/Transaction.cs:191, 213, 224` evaluate `pkg.Name` before `TryAddPackage` / `TryRemovePackage` runs `ThrowIfDisposed`, the `pkg == default` check, and `pkg.ThrowIfNotOwned()`. Consequences: `default(PackageView)` throws `InvalidOperationException` instead of `ArgumentException`; a disposed transaction reads native memory before `ObjectDisposedException`; and every successful call allocates a UTF-16 `string` that is discarded.

**BUG — `PackageSnapshot(LoadedPackage)` disagrees with `LoadedPackage.ToSnapshot()` on disposal.**
`src/Orson.Alpm/Package/PackageSnapshot.cs:73-80` reads `package.View`, which skips `ThrowIfNotOwned()`, so a disposed or disowned wrapper surfaces `AlpmLifetimeException`. `LoadedPackage.ToSnapshot()` (`src/Orson.Alpm/Package/LoadedPackage.cs:171`) throws `ObjectDisposedException` first. Pick one contract and test both entry points.

Missing tests:

- `default(PackageView)`: property read throws `InvalidOperationException`; `ToString()` answers `""`; passing it to `CheckDependencies`, `CheckConflicts`, `FindSatisfier`, `AddPackage`, and `RemovePackage` throws `ArgumentException`.
- `PackageView` equality: two views of the same `_alpm_pkg_t*` are equal and share a hash code; views of different packages are not; `default` does not throw in `Equals` / `==` / `GetHashCode`.
- `NameUtf8` / `VersionUtf8` / `DescriptionUtf8` throw `AlpmLifetimeException` after invalidation, and answer an empty span when the native value is absent.
- `GetSignature()` returns `null` for an unsigned package and non-empty bytes for a signed one.
- `CheckMd5Sum()` on a sync-database package: matching digest answers `true`; mismatch answers `false` without throwing (`PackageView.Seams.cs:42-48`).
- `SetReason` on a sync-database package reports the `WrongArguments` failure instead of mutating anything.
- `LoadedPackage`: a view captured **before** `transaction.AddPackage(loaded)` must throw `AlpmLifetimeException` with `InvalidatedBy == "the hand-over to a transaction"` immediately after the hand-over; `loaded.View` / implicit conversion before disposal; idempotent `Dispose`; registry sweep on `AlpmSession.Dispose()`; `PackageFiles`, `PackageBackupFiles`, `PackageLicenses`, `PackageGroups`.
- `PackageSnapshot(LoadedPackage)` and `PackageSnapshot(LoadedPackage, includeFiles)`; `IPackageMetadata.Files` / `BackupFiles` are `null` when `includeFiles` is false and populated when true, for all three implementations.
- `PackageVersion` exact SBO boundary: 30 UTF-8 bytes stays inline, 31 bytes allocates; the same with multibyte text whose UTF-16 length is below 30. `CompareTo` with `default` / empty; `CompareTo(object)` with a foreign type throws; `TryFormat` with `default(PackageVersion)`; the string constructor path.
- `AlpmList<T>.Enumerator`: `Current` before the first `MoveNext` and after the end throws `InvalidOperationException`; `Reset` rewinds; `Current` / `MoveNext` / `Reset` after `Dispose` throw `ObjectDisposedException`.
- `FileList`: has no `ToArray()`; add one for the snapshot path (§3.1) and test that it returns `Array.Empty<PackageFile>()` for an empty list and preserves order.
- `PackageChangelogStream`: multi-chunk reads, `Read(Span<byte>)` with an empty span, reads after `Dispose`, and `CanRead` / `CanSeek` / `CanWrite`.

### 2.4 Callbacks, events, and formatters

- `LogMessageFormatter` boundary: a 511-byte message stays on the stack buffer; a 512-byte message takes the `ArrayPool<byte>` second-pass path (`LogMessageFormatter.cs:47`). Also `format != null, vaList == null`.
- `Utf8StringCache`: non-empty → empty (`""u8`) → non-empty resets `_hasValue` correctly; same-length different bytes miss the cache; `Release()` returns the pooled buffer and leaves the cache reusable.
- `AlpmEvent.FromUnion`: unknown type throws `ArgumentException`; `OptionalDependencyRemoval`, `DatabaseMissing`, `HookStart`, `HookDone`, `HookRunDone`, `PackageRetrieveStart`, `PackageRetrieveDone`; a `PackageView` carried by an event is retired when the callback returns.
- `AlpmCallbacks.ResolvePackageLifetime`: the `LocalDatabase` branch (`AlpmCallbacks.Questions.cs:166-169`) and the sync-database branch. Both currently run only with `null` package pointers in `QuestionDispatchTests`.
- `AlpmCallbacks.ResolvePackageViews`: a non-empty native `_alpm_list_t*` for `RemoveUnresolvablePackages` and `SelectProvider`. Current dispatch tests pass `null` lists.
- Re-entrancy guard: mutating any `On*` question handler or `EnabledLogLevels` from inside an event, progress, download, or question handler throws. `HandlerException` has a setter that skips `ConfigureGuard` (`AlpmCallbacks.cs:491`) and needs a decision plus a test.

### 2.5 Transient allocators

- Pass a non-array `IReadOnlyCollection<T>` (`List<T>`, `AlpmList<PackageView>`, `AlpmList<SyncDatabase>`) so the `Count` + enumeration contract is exercised.
- Two or more heap chunks in one builder scope, then explicit `Dispose()`; verify the linked-chain release and that a second `Dispose()` is safe.
- Distinguish the two arenas in the string builder. `AssertValidStringList` currently checks both node and string pointers against `sizeof(TransientAlpmStringListAllocator)`, so a write into the wrong arena cannot fail the check.

### 2.6 F# layer

`src/Orson.Alpm.FSharp/Library.fs` is still the `module Say` template. `Orson.Alpm.FSharp.fsproj` does not reference `Orson.Alpm.csproj`, and no F# test project exists. The UTF-8 log adapter paths (synchronous stream sink vs actor copy) from `reports/callback-integration-validation-todo.md` are unimplemented.

Forward hazard: `src/Orson.Alpm.FSharp/DESIGN.md:444-456` sketches `Database.packages: Database -> seq<PackageView>` and `#IPackageMetadata` parameters. Upcasting `AlpmList<PackageView>` to `seq<PackageView>` boxes its 80-byte enumerator, and `Seq.filter` / `Seq.map` add closures. Expose `AlpmList<PackageView>` directly, or provide `inline` generic loops, before implementing those signatures.

## 5. Heaptrack leak detection: placement decision

Keep native leak detection out of `Orson.Alpm.Tests`.

- The xUnit runner is multi-threaded, loads assemblies dynamically, and runs the IL audit. Heaptrack's differential method (`heaptrack_print --diff N1 N2`) needs deterministic scaling; runner noise breaks it.
- The heaptrack run needs `LD_PRELOAD`, debug symbols for `libalpm.so` and `libc.so.6`, and pinned parser output. The unit suite needs none of that and must stay fast.
- Recommended layout:
  - `tests/Orson.NativeLeakProbe/` — console app, `IsTestProject=false`, friend access via `InternalsVisibleTo`. CLI: `<scenario> <iterations>`. Deterministic warm-up before the measured loop. Scenarios per `reports/heaptrack-testing-pipeline-plan.md`.
  - `scripts/run-heaptrack-probe.py` — locate `heaptrack` / `heaptrack_print`, run both counts, parse the `MEMORY LEAKS` block, assert allocation-site scaling, retain `.zst` profiles and the diff on failure.
  - CI: nightly, plus a path filter on `src/Orson.Alpm/Interop/**` and `src/Orson.Alpm/bindings/**`.
- The probe is not a substitute for functional ownership tests. `CFreeExtern` global resolution already has coverage in `ListOwnershipTests` / `TransientAlpm*AllocatorTests`; heaptrack adds site-level leak evidence.
